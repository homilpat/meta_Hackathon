## 목표
기존 기능을 보존하며 (1) 조사 계산·근거 연결과 제한 수정 루프로 업무 완수 신뢰성을 개선하고
(2) 검사 XLSX 한 양식을 읽어 사람이 열 연결·오류를 확인하고 사건에 연결한 뒤 문서와 대조하는 흐름을 구현하라.
사내메일·사내 API 연동·회사별 XLSX 출력·제출 outbox는 이번 필수 범위에서 제외한다. 기존 DOCX/PDF 출력은 보존하라.
계획만 제시하고 끝내지 말고, 환경에서 실행 가능한 코드·검증·문서까지 진행하라.

## R1 — 평가의 오류부터 수정
- 사람 판정 없음이 모든 노출 도구에서 성립하는지 독립 테스트하라.
- AgentEvals의 superset 도구 포함과 첫 호출 순서 assertion을 분리하라.
- 인젝션 경고와 확정 주장을 별도 검사하되 실제 지시 오염을 놓치지 마라.
- 개발/검증 데이터와 정답을 분리하고 기존 기록을 덮어쓰지 마라.
- 고정 문서 추출 입력으로 후속 행동을 먼저 평가하라.

## R2 — 계산 근거와 제한 수정
- 계산 ID에 사건·값·단위·연산·입력 근거·필터·누락 정책·분모·입력 버전을 결합하라.
- 모델은 계산 ID를 참조하고 서버가 보고서의 값/근거를 해소하게 하라.
- 새 계산은 기존 도구 계층의 허용된 계산 도구로 요청하게 하라.
- 타 사건·stale·잘못된 필드/단위·분모·근거 종류를 차단하라.
- schema→근거/계산→필수 항목 검사 후 구조화된 오류를 반환하여 제한 수정하라.
- 공통 호출/시간/비용·수정 상한과 반복 오류 조기 중단을 적용하라.
- 권한 거부를 우회하거나 실패 주장을 삭제해 검증 통과하는 편법을 허용하지 마라.
- 필수 항목 미완수·안전 중단·부분 성공을 전체 완료와 구분하라.
- 기존 보고서 호환/migration 및 실행 상태·감사·사용량 이력을 보존하라.

## R3 — 개선 검증
- 정상/누락/충돌/중복/도구 실패/권한 거부/stale/인젝션 짝 테스트를 실행하라.
- 이전 도구 반환 ID·값·버전의 후속 사용을 검사하라.
- 첫 시도/제한 수정 후 성공률, 반복 pass^k, 필수 항목 완수, 복구 가능한 오류의 복구율,
  허위 완료·안전 중단·지연·호출·비용을 분리하라.
- baseline과 후보는 같은 fixture/평가기/조건으로 비교하라. 후보를 실행하지 않은 replay는 신규 성능이 아니다.
- 안전 불변식 위반은 한 건이라도 gate 실패다. 품질 목표는 교정 baseline 후 held-out 검증 전에 고정하라.
- 의미 타당성은 고정 루브릭의 사람 검토 또는 미평가로 남겨라.

## X1 — 검사 XLSX 입력·미리보기
- 기존 Intake/첨부·권한·감사 구조를 재사용하고 XLSX 합성 참조 양식 한 종류부터 지원하라.
- 파일 hash/버전·업로더·시간과 시트 목록·헤더·행 번호·원본 행 미리보기를 제공하라.
- 품번/LOT/검사일/검사 수량/불량 수량/측정 항목·값·단위의 열 mapping을 추천하고 사람이 확인·수정하게 하라.
- 고정 양식은 결정론적 mapping을 기본으로 하며 LLM 의존성을 불필요하게 늘리지 마라.
- 파일·압축 해제·시트/행/열·시간 상한, 손상/암호화/미지원 형식·숨김 범위 정책을 명시하라.
- 매크로·수식·외부 링크를 실행하지 말고, 임의 외부 URL/서버 경로로 접근하지 마라.

## X2 — 값 검증·원본 추적·사건 연결
- 원본 셀 값/자료형/표시 형식과 정규화 값을 분리하고 sheet/cell/row·mapping 버전을 보존하라.
- LOT 앞자리 0·긴 식별자·날짜/시간대·소수점·단위를 처리하고 손실된 값을 추측 복원하지 마라.
- 수식 캐시는 최신 계산이 보장되지 않음을 표시하고, 필수 값 확인 불가 시 확정 집계에서 제외/차단하라.
- 누락·중복 후보·날짜/자료형 오류·단위 혼재·불량 수량>검사 수량을 셀/행 단위로 제시하라.
- 중복을 자동 삭제하거나 누락을 0/정상으로 채우지 마라. BLOCK/WARN/INFO와 포함·제외 정책을 정하라.
- 사람이 mapping·오류·포함 행을 확인한 뒤 사건에 연결하라. 업로드만으로 사건 생성/증거 확정을 하지 마라.
- 같은 사건·파일·mapping·범위 재확정은 멱등 처리하고 수정/교체는 새 버전 및 stale 영향으로 연결하라.
- 근거 클릭으로 권한 범위 안에서 원본 행/셀과 정규화 과정을 확인할 수 있게 하라.

## X3 — 문서 대조·조사 연결
- 확정한 행을 기존 EvidenceTools/계산 도구로 제공하고 §27의 계산 ID·입력 근거 묶음을 재사용하라.
- 문서와 XLSX의 품번·LOT·검사/불량 수량을 비교하되 제품·기간·검사 범위·단위·수량 의미를 확인하라.
- 키가 없거나 복수 후보면 임의 결합하지 말고 사람 확인/AMBIGUOUS로 처리하라.
- MATCH/MISMATCH/MISSING/AMBIGUOUS/NOT_COMPARABLE에 양쪽 원본 locator·값·범위·비교 규칙을 남겨라.
- 고객 보고와 내부 검사 사실을 구분하고 충돌을 자동 수정하지 마라.
- 새 파일/재매핑 후 집계·대조·조사·문서의 버전 영향을 확인하라.

## X4 — 검증·HTTP E2E·보고
- 정상·잘못된 열 연결·누락·중복·혼합 단위·앞자리 0·모호한 날짜·수식 캐시 없음·손상/상한 초과·
  문서 수량 충돌·다중 LOT·타 사건 접근·stale·확정 중복 요청 fixture를 만들고 검증하라.
- 실제 바이트 PDF/DOCX+XLSX 업로드→열 확인→오류 처리→사람 확인→사건 연결→대조·집계→
  조사/제한 수정→문서 검토·승인→기존 DOCX/PDF 출력→DB/Queue/감사 재조회 HTTP E2E를 수행하라.
- TEST_DOUBLE E2E, 고정 추출 후속 판단, 파일 파싱 포함 E2E, 실제 모델 평가를 분리하라.
- 32회 중 과제 성공 22/실패 10과 보고서 검증 실패 11을 구분하라.
  tool_failure/summary_fails run 2는 안전한 오류 처리로 success=true지만 보고서 VALIDATION_FAILED다.
  과제 성공·안전 중단·유효 보고서·실제 업무 완료를 따로 보고하라.
- 11개 검증 실패 실행의 묶음(§27.1.1)을 기준으로 회귀 사례를 구성하고 원인별 중복 메시지를 실행 수로 오집계하지 마라.
- 실제 실패 응답이 없으면 인젝션 경고 문맥·계산 오류의 세부 원인을 추정으로 표시하고 trace를 발명하지 마라.
- 검토/수정 포함 소요시간·중요 필드 오류/누락·수정 횟수를 측정하라. 사람 비교가 없으면 사용성/시간 절감은 NOT_MEASURED다.
- 관련 backend/frontend/integration 및 저장소 필수 lint/build를 수행하고 README/상태/추적표를 실제 결과로 갱신하라.
- 변경 파일·요구 ID 매핑·migration/복구·재현 명령·실제 결과/분모·실패·비용·실행 모드·한계·commit SHA·푸시 여부를 보고하라.
- 기본 검증은 무료 로컬 OFFLINE/REPLAY/TEST_DOUBLE이며 유료 모델 호출·외부 전송 0회다.
  신규 LIVE는 기존 승인 예산·명시적 opt-in이 확보된 경우만 실행하라.
- 회사 원본·키·민감 trace·다운로드 데이터를 무단 커밋하지 마라.
- 메일·사내 API·XLSX 출력·발송 outbox를 선제 구현하지 마라. 실제 XLSX 양식 부재는 합성 한 양식 구현을 막는 이유가 아니다.
